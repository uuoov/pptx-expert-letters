# 踩坑手册（每条都真实付过学费）

## XML 操作

1. **run 重建必须链式 addnext**。重建段落时若把每个 run 都 `pPr.addnext(r)` 插到 pPr 后面，后插的会排在先插的前面——**整段文字倒序**。正确做法：维护 `prev` 指针，`prev.addnext(r); prev = r`。
2. **段落定位用文本前缀，不用索引**。模板文本框里有空段落，且不同角色模板空段位置不同（有的在开场白后，有的在末尾）。`para_by('会议时间')` 式定位跨模板稳定。
3. **称呼姓名是多个 run**。模板里"周 佳"可能拆成 2~3 个 run，只改第一个 run 会残留"佳"。做法：整段重建（抓 14pt 普通 rPr 和 20pt 加粗 rPr 各一份做模板）。
4. **克隆表格行后序号列要重编号**，否则每行都是"1"。
5. **deepcopy 行再 append 回 tbl 前先 remove 全部行**，顺序：先在树上 addnext 串好新行 → 全部 remove → 按最终顺序 append。
6. endParaRPr 不清理会残留旧格式隐患，重建段落时一并删除。

## 版面

7. **固定高度文本框的"多行溢出"是隐形炸弹**：正文框高 2.98in + 150% 行距是按行数调好的。任何加行操作（备注行、括注）都必须同步删一个空段，并渲染确认"您的任务环节"与表格间距。
8. **简介页主题框截断**：24pt 时每行约容纳 20 个汉字；估算总行数 >3 就把整框降到 18pt。
9. **信头背景**：页级背景图可能是旧会议的。生成前必须核对背景图与正文会议名一致；不一致时问用户或用母版版。
10. 表格行高是 EMU 字符串（`tr.set('h', str(emu))`），1 in = 914400 EMU。

## 流程

11. **渲染验收不要用 PowerPoint COM**（多数机器 E_FAIL）。用 `soffice --headless --convert-to pdf` + PyMuPDF（页数、空页、文本抽取）。注意 soffice 输出文件名可能是 GBK 乱码，按 `sorted()` 顺序处理而不是按名字匹配。
12. **32 位 Python 偶发 MemoryError**（打开大模板时）：`except MemoryError: gc.collect()` 后重试，实测重试 3 次内必过；模板 `Presentation` 对象做模块级缓存，避免每份重新解析。
13. **目标 pptx 被用户在 PowerPoint/WPS 打开时会 PermissionError**：捕获后提示用户关闭再重跑该文件，不要静默跳过（会造成新旧版本混杂）。
14. **议程图核对**：视觉模型对低分辨率人名会误读（"张 晶"读成"张静"），关键人名/时间要放大裁剪二次确认；议程图底部常被截断（大会总结行），务必确认最后一行。
15. **邀请人交叉核对**：讲者函的邀请人 ≠ 该环节主持函的主人 = 旧议程残留。生成前先列"环节→主持→讲者"对照表互相印证。
16. **换人联动**：换主持牵动 5 处（本人函/上家交接句/上家简介末页/下家交接句/被介绍讲者邀请人）。改数据重跑全量，禁止手补单文件。
17. 简历绝**不虚构**：拿不到就占位"【简历待补充】"，并向用户报告缺谁、缺在哪几页。docx 简历用 `word/document.xml` 按 `<w:p>` 拆段落提 `<w:t>`；pptx 简历注意 `<a:br>` 软换行，按 run 顺序拼接否则丢字。
